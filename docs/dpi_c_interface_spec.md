# DPI-C Co-Simulation Interface Specification

## 1. Overview

This document specifies the DPI-C (Direct Programming Interface - C) co-simulation interface for the mini_corundum FPGA project. The interface enables Python-based test generation tools to feed real network packets into a VCS SystemVerilog simulation.

### 1.1 Purpose
- Bridge Python packet generation tools with SystemVerilog simulation
- Enable real-world protocol testing without hardware
- Verify FPGA RTL against actual packet formats generated by host software

### 1.2 Scope
- DPI-C function interface between C and SystemVerilog
- Packet data flow from Python → C → SystemVerilog → DUT
- XGMII frame injection mechanism
- Supported packet types: ARP, ICMP, UDP/LUDP

## 3. DPI-C Function Interface

### 3.1 Function Specifications

All DPI-C functions use scalar types only to avoid VCS internal bugs with array arguments.

#### 3.1.1 dpi_packet_available()
```c
int dpi_packet_available();
```
- **Returns**: 1 if unread packets exist in buffer, 0 otherwise
- **Side Effects**: Initializes packet buffer on first call if not already done
- **Usage**: Called by SystemVerilog to check if packets need processing

#### 3.1.2 dpi_get_length()
```c
int dpi_get_length();
```
- **Returns**: Length of current packet in bytes (0 if no packet available)
- **Range**: 0 to 9216
- **Usage**: Called to determine how many bytes to read for current packet

#### 3.1.3 dpi_get_byte()
```c
int dpi_get_byte(int idx);
```
- **Parameters**: `idx` - Byte index within current packet (0-based)
- **Returns**: Byte value at index (0-255), or 0 if out of range
- **Range**: `idx` must be 0 <= idx < dpi_get_length()
- **Usage**: Called repeatedly to read packet data byte-by-byte

#### 3.1.4 dpi_next_packet()
```c
void dpi_next_packet();
```
- **Returns**: None
- **Side Effects**: Advances current_packet index to next packet
- **Usage**: Called after all bytes of current packet have been read

#### 3.1.5 dpi_get_total_packets()
```c
int dpi_get_total_packets();
```
- **Returns**: Total number of packets loaded in buffer
- **Usage**: Informational/debugging

#### 3.1.6 dpi_reset_packets()
```c
void dpi_reset_packets();
```
- **Returns**: None
- **Side Effects**: Resets current_packet index to 0
- **Usage**: Allows re-reading packet sequence from beginning

### 3.2 SystemVerilog Import Declarations


## 4. XGMII Frame Injection Protocol

### 4.1 XGMII Interface Basics

The XGMII (10 Gigabit Media Independent Interface) uses:
- **64-bit data bus** (`txd`/`rxd`): 8 lanes × 8 bits each
- **8-bit control bus** (`txc`/`rxc`): One bit per lane

Lane mapping:
```
Lane 0: bits [7:0]    Lane 4: bits [39:32]
Lane 1: bits [15:8]   Lane 5: bits [47:40]
Lane 2: bits [23:16]  Lane 6: bits [55:48]
Lane 3: bits [31:24]  Lane 7: bits [63:56]
```

### 4.2 XGMII Control Characters

| Value | Name | Description |
|-------|------|-------------|
| 0x07  | IDLE | Inter-frame fill |
| 0xFB  | START | Start of frame (first byte) |
| 0xFD  | TERM | Terminate frame |
| 0xFE  | ERROR | Error indication |

### 4.3 Frame Transmission Sequence

```
Cycle 0:  [IDLE][IDLE][IDLE][IDLE][IDLE][IDLE][IDLE][START]  txc=0x01
Cycle 1:  [Byte7][Byte6][Byte5][Byte4][Byte3][Byte2][Byte1][Byte0]  txc=0x00
Cycle 2:  [Byte15][Byte14][Byte13][Byte12][Byte11][Byte10][Byte9][Byte8]  txc=0x00
...
Cycle N:  [TERM][ByteN][ByteN-1][ByteN-2][ByteN-3][ByteN-4][ByteN-5][ByteN-6]  txc=0x80
Cycle N+1: [IDLE][IDLE][IDLE][IDLE][IDLE][IDLE][IDLE][IDLE]  txc=0xFF
```

### 4.4 Frame Injection Task (SystemVerilog)

```systemverilog
task feed_packet_from_dpi;
    integer i;
    integer pkt_len;
    integer remaining;
    begin
        if (!dpi_packet_available()) return;

        pkt_len = dpi_get_length();

        i = 0;
        while (i < pkt_len) begin
            @(posedge clk);

            if (i == 0) begin
                // First cycle: Start + data
                sfp0_rxd[7:0]   <= XGMII_START;  // 0xFB
                sfp0_rxc[0]     <= 1'b1;

                if (pkt_len >= 8) begin
                    sfp0_rxd[15:8]  <= dpi_get_byte(0);
                    sfp0_rxd[23:16] <= dpi_get_byte(1);
                    sfp0_rxd[31:24] <= dpi_get_byte(2);
                    sfp0_rxd[39:32] <= dpi_get_byte(3);
                    sfp0_rxd[47:40] <= dpi_get_byte(4);
                    sfp0_rxd[55:48] <= dpi_get_byte(5);
                    sfp0_rxd[63:56] <= dpi_get_byte(6);
                    sfp0_rxc[7:1]   <= 7'b0000000;
                    i = i + 7;
                end else begin
                    // Short packet handling
                    remaining = pkt_len - 1;
                    if (remaining >= 1) sfp0_rxd[15:8]  <= dpi_get_byte(0);
                    // ... more bytes ...
                    if (remaining >= 7) begin
                        sfp0_rxd[63:56] <= XGMII_TERM;  // 0xFD
                        sfp0_rxc[7]     <= 1'b1;
                    end
                    i = pkt_len;
                end
            end else if (i + 8 >= pkt_len) begin
                // Last cycle: data + terminate
                remaining = pkt_len - i;
                sfp0_rxd[7:0]   <= dpi_get_byte(i);
                // ... more bytes ...
                if (remaining >= 8) begin
                    sfp0_rxd[63:56] <= dpi_get_byte(i+7);
                    sfp0_rxc        <= 8'h00;
                    i = i + 8;
                end else begin
                    sfp0_rxd[63:56] <= XGMII_TERM;  // 0xFD
                    sfp0_rxc        <= {1'b1, 7'b0000000};
                    i = pkt_len;
                end
            end else begin
                // Middle cycle: all data
                sfp0_rxd[7:0]   <= dpi_get_byte(i);
                sfp0_rxd[15:8]  <= dpi_get_byte(i+1);
                sfp0_rxd[23:16] <= dpi_get_byte(i+2);
                sfp0_rxd[31:24] <= dpi_get_byte(i+3);
                sfp0_rxd[39:32] <= dpi_get_byte(i+4);
                sfp0_rxd[47:40] <= dpi_get_byte(i+5);
                sfp0_rxd[55:48] <= dpi_get_byte(i+6);
                sfp0_rxd[63:56] <= dpi_get_byte(i+7);
                sfp0_rxc        <= 8'h00;
                i = i + 8;
            end
        end

        // Send idle cycles after packet
        repeat(12) begin
            @(posedge clk);
            sfp0_rxd <= 64'h0707070707070707;
            sfp0_rxc <= 8'hff;
        end

        // Advance to next packet
        dpi_next_packet();
    end
endtask
```

## 5. Packet Format Specifications

### 5.1 ARP Request Packet (60 bytes)

```
Ethernet Header (14 bytes):
  Destination MAC: FF:FF:FF:FF:FF:FF (Broadcast)
  Source MAC:      02:00:00:00:00:01
  EtherType:       0x0806 (ARP)

ARP Packet (28 bytes):
  Hardware Type:    0x0001 (Ethernet)
  Protocol Type:    0x0800 (IPv4)
  Hardware Length:  0x06
  Protocol Length:  0x04
  Opcode:           0x0001 (Request)
  Sender MAC:       02:00:00:00:00:01
  Sender IP:        192.168.1.199 (0xC0A801C7)
  Target MAC:       00:00:00:00:00:00
  Target IP:        192.168.1.128 (0xC0A80180)

Padding (18 bytes):
  Zero-filled to reach minimum 60 bytes
```

### 5.2 ICMP Echo Request Packet (Variable length)

```
Ethernet Header (14 bytes):
  Destination MAC: 02:00:00:00:00:00 (FPGA MAC)
  Source MAC:      02:00:00:00:00:01
  EtherType:       0x0800 (IPv4)

IP Header (20 bytes):
  Version/IHL:     0x45 (IPv4, 5 words)
  DSCP/ECN:        0x00
  Total Length:    20 + 8 + payload_size
  Identification:  0x0000
  Flags/Fragment:  0x4000 (Don't Fragment)
  TTL:             64
  Protocol:        0x01 (ICMP)
  Header Checksum: Calculated
  Source IP:       192.168.1.199
  Dest IP:         192.168.1.128

ICMP Header (8 bytes):
  Type:            0x08 (Echo Request)
  Code:            0x00
  Checksum:        Calculated
  Identifier:      0x1234
  Sequence:        0x0001

Payload (default 32 bytes):
  0x00, 0x01, 0x02, ... 0x1F
```

### 5.3 LUDP START Command Packet

```
Ethernet Header (14 bytes):
  Destination MAC: 02:00:00:00:00:00
  Source MAC:      02:00:00:00:00:01
  EtherType:       0x0800 (IPv4)

IP Header (20 bytes):
  Version/IHL:     0x45
  Total Length:    20 + 8 + 16 (LUDP payload)
  Protocol:        0x11 (UDP)
  Source IP:       192.168.1.199
  Dest IP:         192.168.1.128

UDP Header (8 bytes):
  Source Port:     12345
  Dest Port:       1234 (LUDP_PORT)
  Length:          8 + 16
  Checksum:        0x0000 (optional)

LUDP Payload (16 bytes, little-endian):
  Magic:           0xDA01 (2 bytes)
  Type:            0x02 (PKT_CMD) (1 byte)
  Flags:           0x00 (1 byte)
  CMD ID:          0x00000001 (4 bytes)
  Opcode:          0x0001 (CMD_START) (2 bytes)
  Arg1:            0x00000000 (4 bytes)
  Arg2:            0x0000 (2 bytes)
```

## 7. Known Limitations and Constraints

### 7.1 VCS Compatibility

| Issue | Description | Workaround |
|-------|-------------|------------|
| Array Arguments | `input byte data[]` causes assertion failure in vcs_fence.c | Use scalar `dpi_get_byte(idx)` |
| File I/O in DPI | `fopen`/`fread` may cause VCS crashes | Pre-load packets in C code |
| Socket Operations | Unix domain sockets trigger VCS internal errors | Use file-based or pre-loaded approach |

### 7.2 Packet Size Limits

- Maximum packet size: 9216 bytes (jumbo frame support)
- Maximum packet count: 16 packets in buffer
- XGMII interface: 64-bit data width

### 7.3 Timing Constraints

- Clock period: 6.4ns (156.25 MHz XGMII clock)
- Inter-packet gap: Minimum 12 idle cycles
- Packet read from DPI: One byte per function call
